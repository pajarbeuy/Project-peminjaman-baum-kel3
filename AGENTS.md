## Instruksi utama
- Jangan mengarang kebutuhan. Jika sumber tidak jelas, catat pertanyaan/open issue dan minta keputusan sebelum implementasi yang berisiko.
- Jangan mengubah kebutuhan bisnis, alur approval, model data penting, kontrak API, atau konfigurasi keamanan tanpa menjelaskan dampak dan meminta persetujuan.
- Periksa struktur repository dan konvensi yang sudah ada sebelum membuat file atau memilih library.
- Jangan menimpa file pengguna atau dokumen sumber secara diam-diam.
- Ikuti stack yang sudah dipilih proyek. Jangan mengganti framework atau menambah dependency besar tanpa alasan.
- Untuk perubahan kode, sertakan tes yang relevan dan jalankan pemeriksaan yang tersedia.
- Untuk deliverable perencanaan, jumlah sprint harus tepat 11 sesuai arahan PM, sambil mencatat bahwa SRS menyebut lima sprint/10 minggu sebagai konflik dokumentasi.
- Jangan mengklaim tes lulus jika belum dijalankan. Laporkan perintah, hasil, dan batasan pengujian.
